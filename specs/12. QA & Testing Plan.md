# 1. Purpose

This document defines the quality assurance and testing strategy for the Wireless Connect Online Store.

The goal is to ensure:

- Customers can browse, cart, and checkout successfully
- Admins can manage inventory and orders
- Staff can manage device intake, testing, and IMEI verification
- Warranty records are created and searchable
- Payments are reliable
- Inventory updates correctly
- Private data stays protected
- The site is ready for production launch

---

# 2. Testing Principles

1. Test critical money flows first.
2. Test inventory accuracy carefully (atomic decrement, oversell protection).
3. Test admin permissions.
4. Test mobile experience.
5. Test Stripe webhooks — including idempotency and duplicate delivery.
6. Test RLS/security policies.
7. Do not rely only on manual testing.
8. Every sprint should end with a test pass.
9. Test localization as a first-class feature.
10. Verify English fallback behavior.
11. Verify customer locale persistence.
12. Test security boundaries — IDOR, rate limiting, role escalation.
13. Test compliance requirements — hold period, seller identity, tax calculation.
14. Test error pages — custom 404/500 must not expose stack traces.

## Oversell Protection

Test:

```text
Two concurrent checkout sessions for the same product (quantity = 1)
→ Atomic decrement: UPDATE ... WHERE quantity > 0 RETURNING id
→ Only one transaction succeeds
→ Second transaction detects oversell and fails gracefully
→ Customer shown "item no longer available" message
→ No duplicate sale created
```

## Tracking Number Enforcement

Test:

```text

→ Error: "Tracking number and carrier are required to mark an order as Shipped"
```
