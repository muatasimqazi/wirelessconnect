# 1. Purpose

This document defines the admin dashboard requirements for the Wireless Connect Online Store.

The admin dashboard allows Wireless Connect staff to manage online inventory, product intake, device testing, IMEI verification, product images, orders, coupons, warranties, and store settings.

The dashboard should be simple, fast, and focused on daily store operations. It should not feel like enterprise software.

---

# 2. Admin Dashboard Goals

## Business Goals

1. Allow staff to list used phones quickly.
2. Allow staff to manage available inventory accurately.
3. Allow staff to process online orders.
4. Allow staff to update local pickup and shipping statuses.
5. Allow staff to manage discounts and store settings.
6. Prevent accidental exposure of private product/customer data.
7. Standardize used-device intake, testing, grading, and publishing.
8. Ensure devices are activation-ready before being listed online.
9. Track warranty and fulfillment status clearly.
10. Support English/default product content and Spanish storefront content where available.

## UX Goals

1. Mobile-friendly, but optimized for desktop/tablet use.
2. Minimal clicks for adding a product.
3. Clear order status management.
4. Fast product search and filtering.
5. Clear success/error messages.
6. No confusing technical language.
7. Make device intake fast and checklist-driven.
8. Reduce mistakes when entering IMEI, battery health, condition, and warranty data.
9. Keep admin UI English-only for MVP while allowing staff to enter localized storefront content.

# 3. Admin User Roles

## Staff

Can:

- Access admin dashboard
- Create products
- Edit products
- Upload product images
- Adjust inventory
- Complete device intake checklist
- Record testing results
- Record IMEI verification result
- Record condition grade
- Manage product warranty fields
- Add Spanish storefront content when available
- View orders
- Update order statuses
- View customer contact details for order fulfillment
- Create/edit coupons if allowed by app setting

Cannot:

- Promote users to admin
- Delete critical data permanently
- Access service credentials
- Change role permissions
- View system logs unless specifically allowed

## Admin

Can:

- Do everything staff can do
- Manage staff users in a future version
- Manage global store settings
- View private fields
- Archive/delete records where allowed
- Configure feature flags

```text

→ Processing
→ Shipped

```

- Order is not picked up

MVP can show refunded status, but actual refund action may remain manual in Stripe Dashboard.

# 9.4 Status Update Notifications

When admin marks order as `Ready for Pickup`:

- Send pickup ready email to customer.
Use the order's `customer_locale` for the customer email.

When admin marks order as `Shipped`:

- Send shipping email to customer.
Use the order's `customer_locale` for the customer email.

When admin marks order as `Cancelled`:

- Optionally send cancellation email in future.

Email failures should not block the status update.

# 24. Admin Security Rules

1. Admin routes must be server-protected.
2. Admin actions must verify role server-side.
3. Public users must not access private fields.
4. Product IMEI, serial number, and cost are admin-only.
5. Customer data should only be shown when needed for order fulfillment.
6. Service role key must stay server-only.
7. File uploads must validate file type and size.
8. Destructive actions should require confirmation.
9. Prefer archive over permanent delete.
10. Role changes should be admin-only.
11. IMEI and serial number should be visible only to staff/admin.
12. Cost and acquisition source should be visible only to staff/admin.
13. Customer locale may be visible for support but must not affect authorization.
14. Admin UI remains English-only for MVP.

15. Internal-only intake images must never appear publicly.
16. Publishing gates must be enforced server-side, not only through admin UI.
17. Warranty claim notes must be staff/admin-only.
18. Customers may view safe warranty information, but only staff/admin can update claim status or claim notes.

# 27. Acceptance Criteria

The admin dashboard is complete for MVP when:


1. Only staff/admin users can access `/admin` routes.
2. Non-admin customers cannot access admin pages.
3. Staff/admin users can view dashboard metrics.
4. Staff/admin users can view product list.
5. Staff/admin users can create products.
6. Staff/admin users can edit products.
7. Staff/admin users can upload product images.
8. Staff/admin users can set a primary product image.
9. Staff/admin users can publish, draft, archive, or mark products sold out.
10. Staff/admin users can adjust inventory quantity.
11. Staff/admin users can create and manage device intake records.
12. Staff/admin users can complete testing checklists.
13. Staff/admin users can record IMEI verification results.
14. Products cannot be published until required intake/testing/verification fields are complete.
15. Staff/admin users can manage warranty fields.
16. Staff/admin users can manage Spanish product description and SEO fields when available.
17. Staff/admin users can mark intake images as internal-only.
18. Internal-only images do not appear on public product pages.
19. Staff/admin users can view and update warranty claim status.
20. Publishing gate checklist clearly shows missing requirements before activation.
21. Staff/admin users can view order list.
22. Staff/admin users can view order details.
23. Staff/admin users can update order statuses.
24. Pickup-ready status triggers a customer email.
25. Shipped status triggers a customer email.
26. Staff/admin users can create and edit coupons.
27. Admin users can update store settings.
28. Private fields are visible only in admin.
29. Admin actions use server-side authorization.
30. All forms use Zod validation.
31. Loading, empty, and error states are implemented.
32. Destructive actions require confirmation.
33. The dashboard works on desktop and mobile.
34. The MVP does not include repairs, trade-ins, reports, or customer management unless explicitly requested.
