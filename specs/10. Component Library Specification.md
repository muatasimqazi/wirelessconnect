# 1. Purpose

This document defines reusable UI components for the Wireless Connect Online Store.

Claude Code should use this document to build consistent storefront, checkout, account, and admin UI.

---

# 2. Component Principles

1. Use shadcn/ui as the base.
2. Use Tailwind CSS for styling.
3. Use TypeScript props.
4. Mobile-first by default.
5. Accessible by default.
6. Keep components reusable.
7. Avoid business logic inside visual components.
8. Prefer composition over large components.
9. Use loading, empty, error, and disabled states.
10. Match the UX & Design Guidelines.
11. All customer-facing components must support localization.
12. Do not hardcode customer-facing English text.
13. Customer-facing text should come from translation files or localized data fields.
14. Components should allow longer translated text without breaking layout.
15. Admin components may remain English-only for MVP.

Variants:

```text

outline

```

Sizes:

```text
sm
md
lg

```

Props:

```ts
type ButtonProps = {
  variant?: "primary" | "secondary" | "outline" | "ghost" | "destructive" | "link"
  size?: "sm" | "md" | "lg" | "icon"
  loading?: boolean
  disabled?: boolean
  ariaLabel?: string
  children: React.ReactNode
}
```

Accessibility:

- Must support keyboard focus
- Must show loading state
- Minimum mobile tap height: 44px
- Icon-only buttons must include localized `ariaLabel`

# 4. Internationalization Components

## LanguageSwitcher

Purpose:

Allows customers to switch between supported storefront languages.

Props:

```ts
type LanguageSwitcherProps = {
  currentLocale: SupportedLocale
  supportedLocales: SupportedLocale[]
  preserveCurrentPath?: boolean
  variant?: "inline" | "dropdown" | "compact"
}
```

Requirements:

- Must be available in the storefront header.
- Must be available inside the mobile menu.
- Must preserve the current page when possible.
- Must preserve cart and auth session.
- Must update `wc_locale` cookie.
- For signed-in users, should update `profiles.preferred_locale` when appropriate.

Display labels:

```text
English
Español
```

Accessibility:

- Must be keyboard accessible.
- Must include an accessible label such as `Change language`.

---

## LocalizedText

Purpose:

Small wrapper/helper component for rendering translated UI strings when useful.

Props:

```ts
type LocalizedTextProps = {
  translationKey: string
  values?: Record<string, string | number>
  fallback?: string
}
```

Requirements:

- Should use translation files through `next-intl`.
- Should not be used when direct `useTranslations()` or server translations are clearer.

---

## LocalizedTooltip

Purpose:

Explains technical phone terms in plain language.

Props:

```ts
type LocalizedTooltipProps = {
  term: "unlocked" | "battery_health" | "clean_imei" | "carrier" | "condition"
  locale: SupportedLocale
  children: React.ReactNode
}
```

Examples:

Unlocked:

```text
Works with most carriers.
```

Battery Health:

```text
Higher battery health means longer battery life.
```

Clean IMEI:

```text
Verified and ready to activate.
```

Requirements:

- Must work on mobile tap and desktop hover/focus.
- Must be accessible by keyboard.
- Must not hide critical information behind tooltip only.

# 13. Accessibility Requirements

All components must:

1. Support keyboard navigation.
2. Use visible focus states.
3. Use semantic HTML.
4. Include labels for form fields.
5. Include alt text for images.
6. Use ARIA only when necessary.
7. Meet WCAG AA color contrast.
8. Maintain 44px minimum tap target on mobile.
9. Language switcher must be keyboard accessible.
10. Tooltip content must be accessible on mobile and desktop.
11. Localized alt text should be used when available.

---

# 14. Loading States

Use skeleton components for:

- Product grid
- Product card
- Product detail
- Cart
- Checkout
- Admin tables
- Admin forms
- Dashboard cards

Avoid blank screens.

Loading states should not contain hardcoded English text.

---

# 19. Acceptance Criteria

The component library is complete when:

1. Components are reusable across pages.
2. Components use TypeScript props.
3. Components follow the UX guidelines.
4. Components work on mobile and desktop.
5. Components include loading/empty/error states where needed.
6. Components meet accessibility requirements.
7. Admin and storefront components are clearly separated.
8. Business logic stays in server actions or feature modules.
9. Product private fields are never rendered publicly.
10. The MVP checklist components are implemented.
11. Storefront components support English and Spanish text.
12. LanguageSwitcher is implemented and accessible.
13. Customer-facing components do not hardcode English labels.
14. Product components support localized display fields.
15. Product images support localized alt text.
16. Customer-facing empty, error, and loading states support localization.
17. Admin UI remains English-only for MVP unless explicitly requested.
