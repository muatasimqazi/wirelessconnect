# 1. Purpose

This document serves as the master implementation roadmap for the Wireless Connect Online Store.

It breaks development into manageable sprints and milestones that Claude Code, Codex, or human developers can execute incrementally.

The objective is to:

- Launch a production-ready MVP quickly
- Reduce implementation risk
- Enable testing after each milestone
- Prevent overengineering
- Create a foundation for future expansion

---

# 2. Project Success Criteria

The MVP is considered successful when:

- Customers can browse products
- Customers can search and filter products
- Customers can purchase products online
- Customers can use the storefront in English or Spanish
- Customers can select local pickup or shipping
- Staff can manage inventory
- Staff can manage orders
- Stripe payments work reliably
- Product inventory updates correctly
- The website is mobile-friendly
- The site is production deployed

---

# 3. Development Methodology

## Principles

1. Build foundation before features
2. Build storefront before admin tools
3. Build catalog before checkout
4. Build checkout before reporting
5. Ship working functionality frequently
6. Maintain deployable code after every sprint

## Workflow

```text
Plan
→ Build
→ Test
→ Review
→ Deploy
→ Next Sprint
```

# 9. Claude Code Execution Instructions

When implementing:

1. Complete one sprint at a time.
2. Do not begin a sprint until the previous sprint passes testing.
3. Use companion documents as the source of truth.
4. Prefer Server Components by default.
5. Use Server Actions for mutations.
6. Use Supabase RLS for data protection.
7. Use Stripe webhooks as payment source of truth.
8. Avoid implementing post-MVP features during MVP development.
9. Maintain deployable code after every sprint.
10. Prioritize simplicity, reliability, and maintainability over feature quantity.
11. Implement localization infrastructure before storefront development.
12. Use next-intl for customer-facing text.
13. Preserve locale when navigating customer-facing routes.
14. Resolve localized content with English fallback.
15. Keep admin dashboard English-only for MVP.
16. Implement device intake before advanced product management.
17. Enforce publishing gates in server actions, not only in UI.
18. Keep intake images private unless explicitly approved for storefront use.
19. Create warranty records from successful Stripe payments.
20. Create warranty records from immutable order item snapshots, not current product values.
21. Implement server-side inventory validation before checkout and after payment confirmation.
22. Timed inventory reservations are post-MVP unless explicitly requested.
