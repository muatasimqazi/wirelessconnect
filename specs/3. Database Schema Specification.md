# Wireless Connect Online Store
## Database Schema Specification

Version: v2.0
Stack: Supabase Postgres, Supabase Auth, Supabase Storage, Stripe

---

# 1. Purpose

This document defines the database structure for the Wireless Connect Online Store. It should be used by Claude Code/Codex to generate:

- Supabase migrations
- Row Level Security policies
- TypeScript database types
- Server actions
- Admin dashboard CRUD flows
- Stripe webhook order syncing

The schema is designed for a used-device business selling phones, tablets, laptops, and accessories nationwide in the U.S., with future support for international sales, repairs, and trade-ins.

---

# 2. Design Principles

1. Keep Phase 1 focused on online sales.
2. Store enough device-specific detail for used phones.
3. Use UUID primary keys.
4. Use enums for controlled statuses.
5. Enable Row Level Security on all customer/admin-facing tables.
6. Keep admin operations server-side only.
7. Avoid storing sensitive payment data; Stripe owns payment details.
8. Keep IMEI data private and admin-only.
9. Support guest checkout and registered customer checkout.
10. Design for future repair, trade-in, and warranty modules.
11. Support English and Spanish localization for MVP.
12. Store customer locale preferences for profiles, orders, emails, repairs, and trade-ins.
13. Store product/category translations in JSONB fields to avoid redesign when adding future languages.
14. Keep admin dashboard data English-first for MVP, but make customer-facing storefront data localization-ready.
15. Validate supported locales at the application layer only — do not use hardcoded CHECK constraints that block future language additions.
16. Ensure webhook processing is idempotent via a dedicated webhook_events table.
17. Use secure guest access tokens for order confirmation lookup — never expose orders via guessable identifiers alone.
18. Record seller identity data for secondhand dealer compliance with Washington State RCW 19.60 and similar laws.
19. Enforce hold periods on device intake records before they can be listed for sale.
20. Use atomic SQL patterns for inventory decrement and coupon redemption to prevent race conditions.

# 6.1 profiles

Stores customer, staff, and admin profile data linked to Supabase Auth.

## Table

```sql
create table public.profiles (
  id uuid primary key references auth.users(id) on delete cascade,
  email text not null,
  full_name text,
  phone text,
  role user_role not null default 'customer',
  avatar_url text,
  preferred_locale text not null default 'en',
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
```

## Notes

- `id` must match `auth.users.id`.
- Default role is `customer`.
- `preferred_locale` stores the customer's preferred storefront/email language.
- Do NOT use a CHECK constraint to restrict locale values — validate at the application layer using the `supported_locales` setting. This allows adding future languages without a schema migration.
- MVP supported locales are `en` and `es`, validated application-side.
- Admin role changes should only happen through service-role server actions or direct Supabase admin console.
- A role-change protection trigger must be added to prevent non-admin users from escalating their own role via direct DB access (see Section 12, Triggers).

## Indexes

```sql
create index profiles_email_idx on public.profiles(email);
create index profiles_role_idx on public.profiles(role);
```

## Important Privacy Rule

`imei`, `serial_number`, `cost`, `acquisition_source`, `internal_device_notes`, and `acquisition_date` are admin-only fields. They should never be returned to public product pages.

Public product views should use a safe database view or server-side query that excludes these fields.

## Localization Notes

English fields are the canonical/default product fields.

`translations` stores customer-facing localized product content.

`seo_translations` stores localized SEO metadata.

Do not translate brand names, model names, SKU, IMEI, serial numbers, or storage values unless there is a standard localized equivalent.

# 6.5 device_intakes

Stores checklist-driven intake records for used devices before they are converted into sellable products. Includes seller identity fields required for secondhand dealer compliance under Washington State RCW 19.60 and similar laws in other states.

## Table

```sql
create table public.device_intakes (
  id uuid primary key default gen_random_uuid(),
  product_id uuid references public.products(id) on delete set null,

  status intake_status not null default 'received',
  created_by uuid references auth.users(id) on delete set null,
  updated_by uuid references auth.users(id) on delete set null,

  brand text not null,
  model text not null,
  storage text,
  color text,
  carrier carrier_type default 'unknown',
  original_carrier carrier_type default 'unknown',
  sku text unique,
  imei text,
  serial_number text,

  -- Seller identity fields (required for RCW 19.60 secondhand dealer compliance)
  seller_full_name text,
  seller_phone text,
  seller_email text,
  seller_id_type seller_id_type,
  seller_id_number_encrypted text,   -- pgp_sym_encrypt(id_number, key) — never stored plaintext
  seller_id_state text,              -- issuing state/country
  seller_id_expiry date,
  seller_address text,
  seller_declaration_signed boolean not null default false,
  seller_declaration_signed_at timestamptz,

  -- Acquisition details
  acquisition_source text,
  acquisition_date date not null default current_date,
  acquisition_payment_method acquisition_payment_method,
  cost numeric(10,2) check (cost is null or cost >= 0),
  supplier_notes text,

  -- Hold period compliance (RCW 19.60 requires devices be held before resale)
  hold_until_date date,              -- must be cleared before status can become 'ready_to_list'
  hold_period_days integer not null default 5,
  hold_period_waived boolean not null default false,
  hold_period_waived_reason text,

  -- IMEI verification
  imei_verification_status verification_status not null default 'not_checked',
  is_clean_imei boolean,
  is_blacklisted boolean,
  is_financed boolean,
  activation_lock_removed boolean not null default false,
  imei_verified_at timestamptz,
  imei_verified_by uuid references auth.users(id) on delete set null,
  imei_verification_service text,    -- e.g., 'CTIA', 'GSMA', 'carrier_direct', 'checkmend'
  imei_verification_notes text,

  -- Testing checklist
  testing_status testing_status not null default 'not_started',
  power_on_passed boolean,
  touchscreen_passed boolean,
  face_or_touch_id_passed boolean,
  cameras_passed boolean,
  speakers_passed boolean,
  microphone_passed boolean,
  charging_port_passed boolean,
  wireless_charging_passed boolean,
  bluetooth_passed boolean,
  wifi_passed boolean,
  cellular_passed boolean,
  buttons_passed boolean,
  battery_health integer check (battery_health is null or (battery_health >= 0 and battery_health <= 100)),
  battery_cycle_count integer check (battery_cycle_count is null or battery_cycle_count >= 0),
  factory_reset_verified boolean not null default false,
  data_wiped_verified boolean not null default false,
  tested_at timestamptz,
  tested_by uuid references auth.users(id) on delete set null,
  testing_notes text,

  -- Grading
  condition device_condition,
  cosmetic_notes text,
  functional_notes text,
  defect_disclosure text,
  included_accessories text,

  -- Listing details
  price numeric(10,2) check (price is null or price >= 0),
  compare_at_price numeric(10,2) check (compare_at_price is null or compare_at_price >= 0),
  warranty_days integer not null default 30 check (warranty_days >= 0),
  allow_pickup boolean not null default true,
  allow_shipping boolean not null default true,
  featured_candidate boolean not null default false,

  -- Lifecycle
  converted_to_product_at timestamptz,
  rejected_at timestamptz,
  rejection_reason text,

  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
```

## Notes

- `device_intakes` are staff/admin-only records.
- IMEI, serial number, acquisition source, cost, and notes must never be exposed publicly.
- Seller identity data is legally sensitive — `seller_id_number_encrypted` must be stored encrypted with `pgp_sym_encrypt` and never decrypted client-side.
- `hold_until_date` must be in the past before intake status can be set to `ready_to_list`. This gate must be enforced in server actions.
- `acquisition_date` should default to today and be set by staff at time of device receipt.
- Completed intake records can be converted into `products`.
- When intake is converted to a product, `product_id` must be populated, `status` should become `converted_to_product`, and `converted_to_product_at` should be set.
- Publishing gates should be enforced in server actions before a product becomes active.
- After conversion, `device_intakes` is the historical intake record and `products` becomes the source of truth for active inventory and public storefront data.

## Publishing Gate Requirements

Before a device intake can be converted to an active product, ALL of the following must be true:

1. `imei_verification_status = 'passed'`
2. `is_clean_imei = true`
3. `is_blacklisted = false`
4. `activation_lock_removed = true`
5. `testing_status = 'passed'`
6. `factory_reset_verified = true`
7. `data_wiped_verified = true`
8. `condition` is set
9. `price` is set and greater than 0
10. `hold_until_date` is null OR `hold_until_date <= current_date`

```sql

create index device_intakes_sku_idx on public.device_intakes(sku);
create index device_intakes_imei_idx on public.device_intakes(imei);
create index device_intakes_serial_number_idx on public.device_intakes(serial_number);
create index device_intakes_testing_status_idx on public.device_intakes(testing_status);
create index device_intakes_imei_verification_status_idx on public.device_intakes(imei_verification_status);
create index device_intakes_created_at_idx on public.device_intakes(created_at desc);
create index device_intakes_hold_until_date_idx on public.device_intakes(hold_until_date);
```

# 6.7 carts

Stores cart sessions for guests and authenticated users.

## Table

```sql
create table public.carts (
  id uuid primary key default gen_random_uuid(),
  user_id uuid references auth.users(id) on delete cascade,
  anonymous_id text,
  currency text not null default 'usd',
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  expires_at timestamptz not null default now() + interval '30 days'
);
```

## Notes

- Guest carts use `anonymous_id` stored in a browser cookie.
- Authenticated carts use `user_id`.
- A cart should have either `user_id` or `anonymous_id`.
- Guest carts expire after 30 days. A scheduled cleanup job or pg_cron task should delete expired carts periodically.

## Cleanup Job

```sql
-- Run periodically via pg_cron or Supabase Edge Function
delete from public.carts where expires_at < now() and user_id is null;
```

## Indexes

```sql
create index carts_user_id_idx on public.carts(user_id);
create index carts_anonymous_id_idx on public.carts(anonymous_id);
create index carts_expires_at_idx on public.carts(expires_at);
```

# 6.10 orders

Stores completed or in-progress customer orders.

## Table

```sql
create table public.orders (
  id uuid primary key default gen_random_uuid(),
  order_number text not null unique,

  user_id uuid references auth.users(id) on delete set null,
  customer_email text not null,
  customer_name text,
  customer_phone text,
  customer_locale text not null default 'en',

  -- Secure guest access token for order confirmation lookup
  -- Prevents IDOR on /order-confirmation?id=... URLs
  guest_access_token uuid not null default gen_random_uuid(),

  status order_status not null default 'pending',
  payment_status payment_status not null default 'unpaid',
  fulfillment_method fulfillment_method not null,

  subtotal numeric(10,2) not null default 0,
  discount_total numeric(10,2) not null default 0,
  shipping_total numeric(10,2) not null default 0,
  tax_total numeric(10,2) not null default 0,
  total numeric(10,2) not null default 0,
  currency text not null default 'usd',

  -- Shipping insurance for high-value orders
  shipping_insurance_amount numeric(10,2) not null default 0,

  shipping_address_id uuid references public.addresses(id) on delete set null,
  billing_address_id uuid references public.addresses(id) on delete set null,

  -- Shipping tracking
  tracking_number text,
  shipping_carrier text,           -- e.g., 'USPS', 'UPS', 'FedEx'
  shipped_at timestamptz,

  pickup_location_name text default 'Wireless Connect',
  pickup_location_address text default '14723 Aurora Ave N, Seattle, WA 98133',

  stripe_checkout_session_id text unique,
  stripe_payment_intent_id text,

  -- Tax details (required for multi-state nexus compliance)
  stripe_tax_calculation_id text,
```

## Atomic Coupon Redemption

To prevent race conditions on `used_count`, increment it atomically in a single SQL statement:

```sql
-- Atomic check-and-increment: only succeeds if coupon is valid and under limit
UPDATE public.coupons
SET used_count = used_count + 1
WHERE code = $1
  AND active = true
  AND (usage_limit IS NULL OR used_count < usage_limit)
  AND (starts_at IS NULL OR starts_at <= now())
  AND (expires_at IS NULL OR expires_at > now())
RETURNING id, type, value, minimum_order_amount;
```

If the UPDATE returns 0 rows, the coupon is invalid, expired, or exhausted. Never validate and increment in separate statements.

# 6.15 webhook_events

Stores processed Stripe webhook events to ensure idempotent processing.

## Table

```sql
create table public.webhook_events (
  id uuid primary key default gen_random_uuid(),
  stripe_event_id text not null unique,
  event_type text not null,
  processed_at timestamptz not null default now(),
  payload jsonb,
  error text
);
```

## Notes

- Before processing any Stripe webhook, check if `stripe_event_id` already exists.
- If it exists, skip processing and return 200 to Stripe.
- If it does not exist, insert the event record first (using `ON CONFLICT DO NOTHING`), then process.
- This prevents duplicate order creation, duplicate inventory decrements, and duplicate warranty record creation from repeated webhook deliveries.

## Idempotency Pattern

```sql
-- Attempt to insert; if already processed, skip
INSERT INTO public.webhook_events (stripe_event_id, event_type, payload)
VALUES ($1, $2, $3)
ON CONFLICT (stripe_event_id) DO NOTHING
RETURNING id;

-- If no row returned, event was already processed — skip
```

## Cleanup

Webhook events older than 90 days can be archived or deleted.

## Indexes

## Security Note on SECURITY DEFINER

The `is_admin_or_staff()` and `is_admin()` functions run with elevated privileges. To prevent privilege escalation:

1. The `search_path` must be locked to `public`.

## Role Protection Trigger

Prevents any user from escalating their own role via a direct UPDATE statement. Role changes must go through service-role server actions only.

```sql
create or replace function public.prevent_role_self_escalation()
returns trigger
language plpgsql
security definer
set search_path = public
as $$
begin
  -- If role is being changed and the actor is the same user being updated
  if old.role is distinct from new.role then
    -- Only allow via service role (no auth.uid() means service role context)
    if auth.uid() is not null then
      raise exception 'Role changes are not permitted via client requests.';
    end if;
  end if;
  return new;
end;
$$;

create trigger prevent_role_escalation
before update on public.profiles
for each row execute function public.prevent_role_self_escalation();
```

## Hold Period Gate Trigger

Prevents a device intake from transitioning to `ready_to_list` if the hold period has not expired.

```sql
create or replace function public.enforce_hold_period()
returns trigger
language plpgsql
as $$
begin
  if new.status = 'ready_to_list' and old.status != 'ready_to_list' then
    if new.hold_until_date is not null and new.hold_until_date > current_date then
      raise exception 'Device is in hold period until %. Cannot list before hold period expires.', new.hold_until_date;
    end if;
  end if;
  return new;
end;
$$;

create trigger enforce_intake_hold_period
before update on public.device_intakes
for each row execute function public.enforce_hold_period();
```

4. Atomically decrement product inventory using `UPDATE ... WHERE quantity > 0 RETURNING id`.

6. Create order items if not already created.
7. Send localized confirmation email (using `customer_locale`).

# 15. Inventory Rules

1. A product with `quantity = 0` should be treated as sold out.
2. The UI should not allow checkout for sold-out products.
3. Inventory must be validated again server-side before creating a Stripe Checkout Session.
4. Inventory must be validated again server-side after receiving the Stripe payment confirmation webhook.
5. Inventory should decrement only after confirmed payment via atomic SQL.
6. If payment fails, inventory should not decrement.
7. Admin can manually adjust quantity.
8. Used phones are usually unique items, so most phone products should have `quantity = 1`.
9. Accessories may have quantity greater than 1.
10. Used phones should not be published until intake/testing/IMEI verification gates are complete.
11. Product status should remain `draft` until all required verification fields pass.
12. Oversell prevention uses atomic `UPDATE ... WHERE quantity > 0 RETURNING id` — if no row returned, product is sold out and checkout must be blocked.
13. Timed inventory reservations are post-MVP unless explicitly requested.

## Atomic Inventory Decrement

```sql
-- Atomically decrement inventory; returns the product row if successful
UPDATE public.products
SET quantity = quantity - 1
WHERE id = $product_id
  AND quantity > 0
  AND status = 'active'
RETURNING id, quantity;

-- If no row returned: oversell detected — block checkout and notify admin
```
