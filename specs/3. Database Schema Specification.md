# Wireless Connect Online Store
## Database Schema Specification

Version: v1.0  
Stack: Supabase Postgres, Supabase Auth, Supabase Storage, Stripe

---

# 1. Purpose

This document defines the database structure for the Wireless Connect Online Store. It should be used by Claude Code/Codex to generate:

- Supabase migrations
- Row Level Security policies
- TypeScript database types
- Server actions
- Admin dashboard CRUD flows
- Stripe webhook order syncing

The schema is designed for a used-device business selling phones, tablets, laptops, and accessories, with future support for repairs and trade-ins.

---

# 2. Design Principles

1. Keep Phase 1 focused on online sales.
2. Store enough device-specific detail for used phones.
3. Use UUID primary keys.
4. Use enums for controlled statuses.
5. Enable Row Level Security on all customer/admin-facing tables.
6. Keep admin operations server-side only.
7. Avoid storing sensitive payment data; Stripe owns payment details.
8. Keep IMEI data private and admin-only.
9. Support guest checkout and registered customer checkout.
10. Design for future repair, trade-in, and warranty modules.
11. Support English and Spanish localization for MVP.
12. Store customer locale preferences for profiles, orders, emails, repairs, and trade-ins.
13. Store product/category translations in JSONB fields to avoid redesign when adding future languages.
14. Keep admin dashboard data English-first for MVP, but make customer-facing storefront data localization-ready.

# 6.1 profiles

Stores customer, staff, and admin profile data linked to Supabase Auth.

## Table

```sql
create table public.profiles (
  id uuid primary key references auth.users(id) on delete cascade,
  email text not null,
  full_name text,
  phone text,
  role user_role not null default 'customer',
  avatar_url text,
  preferred_locale text not null default 'en' check (preferred_locale in ('en', 'es')),
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
```

## Notes

- `id` must match `auth.users.id`.
- Default role is `customer`.
- `preferred_locale` stores the customer's preferred storefront/email language.
- MVP supported locales are `en` and `es`.
- Admin role changes should only happen through service-role server actions or direct Supabase admin console.

## Indexes

```sql
create index profiles_email_idx on public.profiles(email);
create index profiles_role_idx on public.profiles(role);
```

# 6.3 products

Stores sellable devices and accessories.

## Table

```sql
create table public.products (
  id uuid primary key default gen_random_uuid(),
  category_id uuid references public.categories(id) on delete set null,

  slug text not null unique,
  title text not null,
  subtitle text,
  description text,
  translations jsonb not null default '{}'::jsonb,

  category_type product_category_type not null,
  brand text,
  model text,
  storage text,
  color text,
  carrier carrier_type default 'unknown',
  original_carrier carrier_type default 'unknown',
  condition device_condition,
  battery_health integer check (battery_health is null or (battery_health >= 0 and battery_health <= 100)),
  battery_cycle_count integer check (battery_cycle_count is null or battery_cycle_count >= 0),

  imei text,
  serial_number text,
  is_clean_imei boolean default false,
  imei_verification_status verification_status not null default 'not_checked',
  imei_verified_at timestamptz,
  imei_verified_by uuid references auth.users(id) on delete set null,
  is_unlocked boolean default false,
  activation_lock_removed boolean not null default false,
  is_tested boolean not null default false,
  testing_status testing_status not null default 'not_started',
  tested_at timestamptz,
  tested_by uuid references auth.users(id) on delete set null,
  testing_notes text,
  is_data_wiped boolean not null default false,
  factory_reset_verified boolean not null default false,
  includes_charger boolean not null default false,
  includes_cable boolean not null default true,
  warranty_days integer not null default 30,

  price numeric(10,2) not null check (price >= 0),
  compare_at_price numeric(10,2) check (compare_at_price is null or compare_at_price >= 0),
  cost numeric(10,2) check (cost is null or cost >= 0),
  acquisition_source text,
  acquisition_date date,
  internal_device_notes text,

  quantity integer not null default 1 check (quantity >= 0),
  sku text unique,
  barcode text,

  status product_status not null default 'draft',
  featured boolean not null default false,
  allow_pickup boolean not null default true,
  allow_shipping boolean not null default true,

  seo_title text,
  seo_description text,
  seo_translations jsonb not null default '{}'::jsonb,

  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
```

## Important Privacy Rule

`imei`, `serial_number`, and `cost` are admin-only fields. They should never be returned to public product pages.

Public product views should use a safe database view or server-side query that excludes these fields.

## Localization Notes

English fields are the canonical/default product fields.

`translations` stores customer-facing localized product content.

Example:

```json
{
  "es": {
    "title": "Apple iPhone 15 Pro Max 256GB Desbloqueado Excelente",
    "subtitle": "Batería 92% • IMEI limpio • Probado",
    "description": "iPhone probado profesionalmente con garantía limitada de 30 días."
  }
}
```

`seo_translations` stores localized SEO metadata.

Example:

```json
{
  "es": {
    "seo_title": "iPhone 15 Pro Max usado en Shoreline, WA",
    "seo_description": "iPhone 15 Pro Max probado profesionalmente con IMEI limpio y garantía de 30 días."
  }
}
```

Do not translate brand names, model names, SKU, IMEI, serial numbers, or storage values unless there is a standard localized equivalent.

```sql

create index products_slug_idx on public.products(slug);
create index products_status_idx on public.products(status);
create index products_featured_idx on public.products(featured);
create index products_brand_idx on public.products(brand);
create index products_model_idx on public.products(model);
create index products_price_idx on public.products(price);
create index products_condition_idx on public.products(condition);
create index products_carrier_idx on public.products(carrier);
create index products_sku_idx on public.products(sku);
create index products_imei_idx on public.products(imei);
create index products_testing_status_idx on public.products(testing_status);
create index products_imei_verification_status_idx on public.products(imei_verification_status);
```

## Search Index

```sql
create index products_search_idx on public.products using gin (
  to_tsvector('english', coalesce(title, '') || ' ' || coalesce(brand, '') || ' ' || coalesce(model, '') || ' ' || coalesce(storage, '') || ' ' || coalesce(color, ''))
);
```

## Localization Search Note

MVP search can index English/default fields only.

Future Spanish search may require:

- A separate generated search document for Spanish
- A language-aware search function
- External search service such as Meilisearch, Typesense, or Algolia

# 6.5 device_intakes

Stores checklist-driven intake records for used devices before they are converted into sellable products.

## Table

```sql
create table public.device_intakes (
  id uuid primary key default gen_random_uuid(),
  product_id uuid references public.products(id) on delete set null,

  status intake_status not null default 'received',
  created_by uuid references auth.users(id) on delete set null,
  updated_by uuid references auth.users(id) on delete set null,

  brand text not null,
  model text not null,
  storage text,
  color text,
  carrier carrier_type default 'unknown',
  original_carrier carrier_type default 'unknown',
  sku text unique,
  imei text,
  serial_number text,

  acquisition_source text,
  acquisition_date date,
  cost numeric(10,2) check (cost is null or cost >= 0),
  supplier_notes text,

  imei_verification_status verification_status not null default 'not_checked',
  is_clean_imei boolean,
  is_blacklisted boolean,
  is_financed boolean,
  activation_lock_removed boolean not null default false,
  imei_verified_at timestamptz,
  imei_verified_by uuid references auth.users(id) on delete set null,
  imei_verification_notes text,

  testing_status testing_status not null default 'not_started',
  power_on_passed boolean,
  touchscreen_passed boolean,
  face_or_touch_id_passed boolean,
  cameras_passed boolean,
  speakers_passed boolean,
  microphone_passed boolean,
  charging_port_passed boolean,
  wireless_charging_passed boolean,
  bluetooth_passed boolean,
  wifi_passed boolean,
  cellular_passed boolean,
  buttons_passed boolean,
  battery_health integer check (battery_health is null or (battery_health >= 0 and battery_health <= 100)),
  battery_cycle_count integer check (battery_cycle_count is null or battery_cycle_count >= 0),
  factory_reset_verified boolean not null default false,
  data_wiped_verified boolean not null default false,
  tested_at timestamptz,
  tested_by uuid references auth.users(id) on delete set null,
  testing_notes text,

  condition device_condition,
  cosmetic_notes text,
  functional_notes text,
  defect_disclosure text,
  included_accessories text,

  price numeric(10,2) check (price is null or price >= 0),
  compare_at_price numeric(10,2) check (compare_at_price is null or compare_at_price >= 0),
  warranty_days integer not null default 30 check (warranty_days >= 0),
  allow_pickup boolean not null default true,
  allow_shipping boolean not null default true,
  featured_candidate boolean not null default false,

  converted_to_product_at timestamptz,
  rejected_at timestamptz,
  rejection_reason text,

  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
```

## Notes

- `device_intakes` are staff/admin-only records.
- IMEI, serial number, acquisition source, cost, and notes must never be exposed publicly.
- Completed intake records can be converted into `products`.
- When intake is converted to a product, `product_id` must be populated, `status` should become `converted_to_product`, and `converted_to_product_at` should be set.
- Publishing gates should be enforced in server actions before a product becomes active.
- After conversion, `device_intakes` is the historical intake record and `products` becomes the source of truth for active inventory and public storefront data.

## Indexes

```sql
create index device_intakes_status_idx on public.device_intakes(status);
create index device_intakes_sku_idx on public.device_intakes(sku);
create index device_intakes_imei_idx on public.device_intakes(imei);
create index device_intakes_serial_number_idx on public.device_intakes(serial_number);
create index device_intakes_testing_status_idx on public.device_intakes(testing_status);
create index device_intakes_imei_verification_status_idx on public.device_intakes(imei_verification_status);
create index device_intakes_created_at_idx on public.device_intakes(created_at desc);
```

# 6.10 orders

Stores completed or in-progress customer orders.

## Table

```sql
create table public.orders (
  id uuid primary key default gen_random_uuid(),
  order_number text not null unique,

  user_id uuid references auth.users(id) on delete set null,
  customer_email text not null,
  customer_name text,
  customer_phone text,
  customer_locale text not null default 'en' check (customer_locale in ('en', 'es')),

  subtotal numeric(10,2) not null default 0,
  discount_total numeric(10,2) not null default 0,
  shipping_total numeric(10,2) not null default 0,
  tax_total numeric(10,2) not null default 0,
  total numeric(10,2) not null default 0,
  currency text not null default 'usd',

  shipping_address_id uuid references public.addresses(id) on delete set null,
  billing_address_id uuid references public.addresses(id) on delete set null,

  pickup_location_name text default 'Wireless Connect',
  pickup_location_address text default '14723 Aurora Ave N, Seattle, WA 98133',

  stripe_checkout_session_id text unique,
  stripe_payment_intent_id text,

  notes text,
  admin_notes text,

  paid_at timestamptz,
  fulfilled_at timestamptz,
  cancelled_at timestamptz,
  refunded_at timestamptz,
  warranty_started_at timestamptz,

  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
```

## Notes

- `order_number` should be human-readable, for example `WC-10001`.
- Use Stripe webhooks to update `payment_status` and `status`.
- `admin_notes` should not be visible to customers.
- `customer_locale` stores the language used for order confirmation and status emails.

# 11. RLS Policy Rules

## Helper Function: is_admin_or_staff

```sql
create or replace function public.is_admin_or_staff()
returns boolean
language sql
security definer
set search_path = public
as $$
  select exists (
    select 1
    from public.profiles
    where id = auth.uid()
    and role in ('admin', 'staff')
  );
$$;
```

## profiles

Rules:

- Users can view and update their own profile.
- Staff/admin can view all profiles.
- Only admins can change roles.

## categories

Rules:

- Everyone can read active categories.
- Staff/admin can create, update, and delete categories.

## products

Rules:

- Everyone can read active products through the public product view.
- Staff/admin can read all products.
- Staff/admin can create, update, and archive products.
- Public users cannot access IMEI, serial number, or cost.

## product_images

Rules:

- Everyone can read images for active products.
- Staff/admin can create, update, and delete images.

## device_intakes

Rules:

- Staff/admin can create, read, update, and archive/reject intake records.
- Customers and public users cannot access intake records.
- IMEI, serial number, acquisition source, cost, and internal notes are staff/admin-only.

## device_intake_images

Rules:

- Staff/admin can create, read, update, and delete intake images.
- Customers and public users cannot access intake images.
- Images marked `internal_only` must never be copied to public product images.

## carts

Rules:

- Users can manage their own cart.
- Guest cart access should be handled through server actions using anonymous cookie IDs.
- Staff/admin should not normally modify carts.

## cart_items

Rules:

- Users can manage items in their own cart.
- Product availability should be validated server-side.

## addresses

Rules:

- Users can view, create, update, and delete their own addresses.
- Staff/admin can view addresses connected to orders.

## orders

Rules:

- Customers can view their own orders.
- Guest orders can be viewed only through secure order lookup tokens or email-based verification.
- Staff/admin can view and update all orders.
- Public users cannot update order status.

## order_items

Rules:

- Customers can view order items for their own orders.
- Staff/admin can view all order items.

## warranties

Rules:

- Customers can view warranty records connected to their own orders.
- Staff/admin can view and update all warranty records.
- Public users cannot access warranty records.
- Device IMEI and serial number in warranty records should only be returned to staff/admin queries unless explicitly needed for customer support.
- Customers cannot update warranty records or claim statuses.
- Only staff/admin can update warranty claim status and claim notes.

## coupons

Rules:

- Public can validate active coupon codes through a server action.
- Staff/admin can manage coupons.

## settings

Rules:

- Public can read safe settings needed for the storefront.
- Public settings may include `default_locale` and `supported_locales` inside the `value` JSON.
- Staff/admin can manage settings.

# 15. Inventory Rules

1. A product with `quantity = 0` should be treated as sold out.
2. The UI should not allow checkout for sold-out products.
3. Inventory must be validated again server-side before creating a Stripe Checkout Session.
4. Inventory should decrement only after confirmed payment.
5. If payment fails, inventory should not decrement.
6. Admin can manually adjust quantity.
7. Used phones are usually unique items, so most phone products should have `quantity = 1`.
8. Accessories may have quantity greater than 1.
9. Used phones should not be published until intake/testing/IMEI verification gates are complete.
10. Product status should remain `draft` until required verification fields are complete.
11. MVP should use server-side inventory validation before Stripe Checkout and after Stripe payment confirmation.
12. Oversell edge cases should be minimized through validation, but full inventory reservation with expiration is future scope unless explicitly requested.

# 23. Claude Code Implementation Notes

When generating code:

1. Prefer server actions for writes.
2. Use Supabase service role only on the server.
3. Never expose service role key to client components.
4. Public storefront product queries should use safe selected fields or the public product view.
5. Validate all writes with zod.
6. Recheck inventory before Stripe Checkout.
7. Decrement inventory only after Stripe payment confirmation.
8. Keep checkout logic idempotent to avoid duplicate orders from repeated webhook events.
9. Add tests for order creation, inventory decrement, and product visibility.
10. Keep Phase 2 tables out of the initial UI unless asked.
11. Customer-facing queries should resolve localized content based on requested locale, with English fallback.
12. Emails should use `customer_locale` when choosing templates.
13. Do not require admin dashboard localization for MVP.
14. Implement publishing gates so used phones cannot become active until required intake, testing, IMEI verification, and reset/wipe checks are complete.
15. Keep intake records staff/admin-only.
16. Create warranty records after successful payment when applicable.
17. Default new used-device products to untested, not data-wiped, and not clean-IMEI verified until verification is completed.
18. Use `warranty_claim_status` enum values instead of free-text claim statuses.
19. Keep `device-intake-images` private and copy only approved public-facing images to `product_images`.
