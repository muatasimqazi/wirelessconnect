# 1. Purpose

This document defines all transactional email templates used by the Wireless Connect Online Store.

The goals are:

- Maintain consistent branding
- Build customer trust
- Improve conversion and retention
- Ensure customers receive important order updates
- Provide implementation guidance for Claude Code

---

# 2. Email Design Standards

All emails should:

- Be mobile friendly
- Use responsive layouts
- Include Wireless Connect branding
- Include store contact information
- Include plain text fallback
- Include clear call-to-action buttons where appropriate

- Quantity

- Order total


If shipping:

```text
Shipping Selected
```

```text

```

### CTA

```text
View Order
```

For authenticated customers: links to `/[locale]/account/orders/[orderNumber]`

For guest customers: links to `/[locale]/order-confirmation?token={{guestAccessToken}}`

The `guest_access_token` UUID must be included in the URL for guest orders — it is the only secure way for guests to view their order.

- Order number
- Order details
- Fulfillment method
- Warranty reminder

### Security Notice

```text
If you did not request a password reset, you can safely ignore this email.
```

## Implementation Note — CRITICAL

**Do NOT implement a custom password reset email via Resend or a custom server action.**

Password reset emails are handled by Supabase Auth internally. To route them through Resend for consistent branding:

1. Go to Supabase Dashboard → Settings → Auth → SMTP.
2. Configure Resend's SMTP endpoint as the custom SMTP provider.
3. Customize the email template in Supabase Auth settings to use Wireless Connect branding.

Implementing a separate custom password reset flow bypasses Supabase Auth's secure token handling and is a security risk.

# 12. Acceptance Criteria

The Email Templates Specification is complete when:

1. Every transactional email has a defined trigger.
2. Every email has a subject line.
3. Every email has preview text.
4. Every email defines required variables.
5. Every email follows Wireless Connect branding.
6. Every email includes store contact information.
7. Every email has a mobile-friendly design.
8. Order Confirmation is sent after successful payment.
9. Pickup Ready is sent after status update.
10. Shipping Confirmation is sent after status update.
11. Email failures do not interrupt order processing.
12. Future repair and trade-in emails are documented but excluded from MVP.
13. Order cancellation email is implemented as required (not optional).
14. Warranty claim received email is implemented and sent in customer locale.
15. Warranty claim status update email is implemented and sent in customer locale.
16. Guest order confirmation email includes `guest_access_token` URL.
17. Password reset email is handled via Supabase Auth SMTP configuration (not a custom Resend implementation).
18. Shipping confirmation email always includes tracking number (required by admin UI gate).
19. All MVP customer emails support English and Spanish.
20. Data deletion request received email is implemented and sent in the requester locale when available.
